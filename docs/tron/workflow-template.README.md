# Шаблон dynamic-workflow для исполнения планов

`workflow-template.js` — канонический скрипт исполнения плана (снят с прогона планов F+G,
2026-07-12; тот же паттерн исполнял планы C2/D/E). Для нового плана скопировать и заменить:

1. `meta` — имя/фазы под задачи нового плана.
2. `CTX` — пути плана(ов), machine-specific заметки (live-эндпоинты, каналы к java-tron,
   ключи). Актуальные значения — в STATUS.md секции «Окружение».
3. Вызовы `verifiedTask(...)` — по одному на задачу плана: `implExtra` (ключевые
   специфики задачи) и `verifyExtra` (что верификатор обязан перепроверить сам).
4. `fableGate(...)` — после каждых двух задач и финальный.

Инварианты процесса (менять нельзя, утверждены пользователем):
- исполнители/верификаторы — model: 'opus'; ревью — model: 'fable';
- верификатор адверсариален: сам перегоняет тесты, сам перепроверяет доменные факты
  по первоисточникам (java-tron через jsdelivr, live-ноды), не доверяет отчёту;
- fix-цикл до 3 (4-я верификация — последняя), фиксы — model: 'opus';
- никакого ослабления тестов/#[ignore]; live-гейты с явным skip-eprintln;
- оркестратор (Fable) пушит и открывает PR сам; агенты НЕ пушат.

Запуск: инструмент Workflow c `script` = содержимое файла (или scriptPath на копию).
